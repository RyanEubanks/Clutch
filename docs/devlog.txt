================================================================================
 CLUTCH DEVLOG
================================================================================

Notes, bugs, and lessons from building Clutch. Newest entries go at the top of
each section.

HOW TO FIND THINGS
  Every entry has a tag you can search for (Ctrl+F / grep):
    [OPEN-xx]      Open issues and things to watch out for
    [TEST-xx]      Bugs caught by automated tests or by running code
    [REVIEW-xx]    Bugs caught by hand, code review, or screenshots
    [MODEL-xx]     Mistakes the AI model made, caught by evals or the math checker
    [ENV-xx]       Setup, environment, and tooling notes
    [DECISION-xx]  Design choices and the reasons behind them
  Search "Files:" plus a file name (e.g. "Files: backend/mathcheck.py") to find
  every entry about that file.

ENTRY FORMAT
  [TAG-xx] Short title
    Date:      when it was found
    Found by:  which test, eval, or person caught it
    Symptom:   what went wrong
    Cause:     why
    Fix:       what changed (or "open" if not fixed yet)
    Files:     where

CONTENTS
  1. Open issues and watch-outs ................ [OPEN]
  2. Caught by tests and test runs ............. [TEST]
  3. Caught by hand, review, or screenshots .... [REVIEW]
  4. Model mistakes caught ..................... [MODEL]
  5. Environment and tooling ................... [ENV]
  6. Design decisions .......................... [DECISION]
  7. Test and eval history

[OPEN-09] Textbook limits
  Date:      Oct 25, 2026
  Note:      - Links go to the book's front page (openstax.org/books/<slug>), not the
               exact section: section URLs couldn't be checked from the sandbox.
             - Chemistry 2e and the math books have no multiple-choice review
               questions, so their textbook questions are glossary questions only.
             - Quiz quotes are still only checked against the student's notes, not
               against the book's passages.
             - Chapter choice is tested on 12 real topics (all right), but a vague
               topic ("Genetics") can still land on a nearby chapter.
  Files:     backend/textbooks.py

[OPEN-08] What still isn't verified
  Date:      Oct 25, 2026 (updated after adding the subject checkers)
  Note:      Verified: Elementary Math, Pre-Algebra, Algebra I and II, Calculus I,
             Geometry, Statistics, Physics. Partly: Chemistry, Spanish I, English,
             U.S./World History, Geography, Civics, Social Studies. Not: Biology,
             French, Programming, Economics, Psychology, custom courses (but any
             course can be checked against the student's notes). Gaps even in
             verified courses: concept questions without notes, word problems,
             proofs, graphing, and calculus answers in chat. Spanish covers only
             present-tense conjugations of 143 listed verbs. Not yet built:
             programming (needs a sandbox). With an OpenStax book imported, its
             course gets textbook questions too (see [DECISION-09], [OPEN-09]).
  Files:     backend/courses.py

[OPEN-07] Arithmetic word problems still can't be checked
  Date:      Oct 25, 2026
  Note:      "If you have 12 apples and get 5 more, how many?" has no written-out
             arithmetic to check, so it stays unchecked. Unchecked number
             questions are ranked last and only used when there aren't enough
             checked ones. Guessing the arithmetic from the words could "fix" a
             key that was right, so it isn't attempted.
  Files:     backend/mathcheck.py (find_arithmetic), backend/app.py

[OPEN-06] The math checker hasn't been run against the real Gemma yet
  Date:      Oct 25, 2026
  Note:      All checker tests use a fake model. Run the real-model eval to see
             how often Gemma writes checkable math, how often its answer key is
             wrong, and why questions get dropped:
               cd backend; python eval_quiz.py            (Ollama running)
             Results: eval_results/quiz-eval-<time>.md (read) and .csv.
             Add the results to [MODEL-03] below.
  Files:     backend/eval_quiz.py

[OPEN-01] Ollama's 4K default context window
  Date:      Oct 24, 2026 (original note)
  Found by:  research while setting up Gemma 4
  Note:      One guide warns that Ollama defaults Gemma 4 to a 4K context window,
             even though the model supports 128K to 256K, and that you should
             override num_ctx for long inputs. That doesn't matter for short
             chats, so ignore it for now. It will matter when you start putting
             whole notes or textbook chapters into the prompt, because the model
             might otherwise cut off the end without telling you.
  Status:    Partly handled. Study material sent to the tutor and the quiz writer
             is capped at DOC_CHAR_BUDGET (default 6000 characters). Raising
             num_ctx in Ollama is still to do; raise DOC_CHAR_BUDGET after that.
  Files:     backend/app.py, backend/.env

[OPEN-02] Gemma e2b gives wrong math in chat and study guides
  Date:      Oct 25, 2026
  Found by:  hand testing (quizzes and study lessons had wrong answers)
  Cause:     gemma4:e2b is the smallest Gemma 4 model (~2B effective params) and
             is unreliable at multi-step math. JSON mode also made it commit to
             an answer before working anything out.
  Fix:       Quizzes: fixed by the SymPy checker (see [MODEL-03]).
             Tutor chat and study guides: OPEN. Options, best first:
               - Use a bigger model (e4b ~6 GB, 12B ~8 GB, 26B ~16-18 GB at 4-bit).
               - Generate in two steps (reason in text first, then format JSON).
               - Turn on Gemma 4's thinking mode (check how through Ollama).
               - SymPy-check the tutor's "Yes, that's right" verdicts.
  Files:     backend/app.py

[OPEN-03] Concept quiz questions can't be machine-checked
  Date:      Oct 25, 2026
  Note:      Only math questions (derivatives, integrals, limits, etc.) are
             verified by SymPy. Concept questions ("what does the chain rule
             apply to?") still depend on the model. Checked questions are picked
             first, and show a "math-checked" tag in the quiz.
  Files:     backend/app.py, backend/mathcheck.py, frontend/src/Quiz.jsx

[OPEN-04] No passwords or access checks
  Date:      Oct 24, 2026
  Note:      Sign-in is username only, and the API trusts whatever user/topic ID
             it's given, so anyone who knows an ID can read that data. Fine for a
             local demo; must be fixed before real students use it.
  Files:     backend/app.py

[OPEN-05] Scanned homework isn't saved
  Date:      Oct 24, 2026
  Note:      Homework text lives only in the browser and is lost on refresh.
             Saving it as a study material (documents table) is a possible next
             step.
  Files:     frontend/src/Homework.jsx, frontend/src/App.jsx

[TEST-16] Textbook quizzes came from the chapter that mentions the topic most
  Date:      Oct 25, 2026
  Found by:  chapter test on real Biology 2e (12 topics)
  Symptom:   "Mitosis" quizzed Meiosis questions; "Evolution" quizzed Vertebrates.
             Searching more passages didn't help.
  Cause:     Chapters were picked by passage matches only, and other chapters say
             "mitosis" more often than the one that teaches it.
  Fix:       Prefer a chapter whose title names the topic, then the chapter whose
             glossary defines it (only in the course's own books: "photosynthesis"
             is also in the Chemistry glossary), then passage matches. 12/12 right.
  Files:     backend/textbooks.py, backend/tests/test_textbooks.py

[TEST-15] Unrelated topics pulled in textbook passages
  Date:      Oct 25, 2026
  Found by:  search dry run on real books
  Symptom:   "Underwater basket weaving" got Ecology passages (via "water"), and
             "Civil War" quizzes included chapter 29 questions.
  Fix:       A search only counts if at least half of the topic's key words are in
             the best passage; quizzes draw on the whole best chapter.
  Files:     backend/textbooks.py

[TEST-14] Some review questions can't be shown as written
  Date:      Oct 25, 2026
  Found by:  import of real Biology 2e and U.S. History
  Symptom:   Questions like "Which structure is labeled B?", options like "A, C, B"
             (labels in a figure), and 5-option questions.
  Fix:       Skip questions that link to or mention a figure, table or graph, have
             letter-sequence options, or don't have exactly 4 options.
  Files:     backend/textbooks.py

[TEST-13] Book metadata lookup always fell through
  Date:      Oct 25, 2026
  Found by:  first import of a real collection file
  Symptom:   "no metadata in its collection file" for every book.
  Cause:     `a.find(...) or b.find(...)`: an XML element with no children counts as
             False in Python, so a found element was thrown away.
  Fix:       Compare with None explicitly.
  Files:     backend/textbooks.py

[TEST-12] Quotes from notes failed on an apostrophe and a comma
  Date:      Oct 25, 2026
  Found by:  groundcheck dry run
  Symptom:   "The nucleus stores the cells DNA, and controls..." wasn't found in
             notes saying "the cell's DNA and controls...".
  Fix:       Compare letters, digits and spaces only. A changed word (DNA -> RNA)
             still fails, as it should.
  Files:     backend/groundcheck.py

[TEST-11] Fact-bank date tags matched the wrong topics
  Date:      Oct 25, 2026
  Found by:  questions_for() dry run
  Symptom:   A "Civil War" topic could get World War questions (shared tag "war"),
             tags like "us" matched any topic containing those letters, and
             "State capitals" also pulled world capitals. Date questions read
             "In what year the U.S. Civil War ended?".
  Fix:       Specific tags only; state vs world capitals by topic words; each date
             fact now stores its own question wording ("did the Civil War end").
  Files:     backend/factbank.py

[TEST-10] A bare "6" counted as a rounded 6.2
  Date:      Oct 25, 2026
  Found by:  statistics dry run (mean of 3, 5, 7, 7, 9)
  Symptom:   Options "6.2" and "6" both matched, so the question was dropped as
             having two right answers.
  Cause:     Whole-number options got a +/-0.5 rounding tolerance.
  Fix:       A whole number only counts as rounded when every option is a whole
             number; next to decimals it means exactly that number.
  Files:     backend/valuecheck.py

[TEST-09] Blank-filling question failed on its trailing period and "\t"
  Date:      Oct 25, 2026
  Found by:  replaying the real Addition quiz (tests/addition_quiz_questions.json)
  Symptom:   "Solve for the missing number: $8 + \text{?} = 15$." couldn't be
             parsed ("15 ." is invalid).
  Cause:     The sentence's final period was captured as part of the equation.
             Also, Gemma wrote "\text" inside JSON, where "\t" means a tab, so it
             was stored as a tab followed by "ext{?}".
  Fix:       Trim trailing punctuation from each side, and turn tab + "ext{" back
             into "\text{" before reading the question.
  Files:     backend/mathcheck.py

[TEST-08] "Evaluate" questions would show their own answer
  Date:      Oct 25, 2026
  Found by:  code review, then test_mathcheck.py::test_evaluate_shows_the_expression_not_the_answer
  Symptom:   op "evaluate" with expr "45 + 23" displayed "Evaluate $68$." Then,
             once shown unevaluated, SymPy reordered it to "23 + 45" and wrote
             (3+4)*2 as "(3 + 4) 2".
  Cause:     Parsing evaluates numbers right away; SymPy's LaTeX sorts terms and
             writes number products by juxtaposition.
  Fix:       tex_as_written(): parse without evaluating, keep the original term
             order, and use a times sign between plain numbers.
  Files:     backend/mathcheck.py

[TEST-07] Showing questions "as written" crashed with NameError: 'Pow'
  Date:      Oct 25, 2026
  Found by:  test_mathcheck.py::test_definite_evaluate_solve_simplify
  Symptom:   Every "simplify" question was dropped with
             "could not parse ...: name 'Pow' is not defined".
  Cause:     Parsing without evaluating (so sqrt(x^2) isn't displayed as |x|)
             builds Add/Mul/Pow objects, and those names weren't in the
             checker's locked-down namespace.
  Fix:       Added Add, Mul, Pow to the allowed SymPy names.
  Files:     backend/mathcheck.py

[TEST-06] "ln|x|" was rejected, then parsed as "lnabs(x)"
  Date:      Oct 25, 2026
  Found by:  eval_quiz.py dry run, then test_mathcheck.py::test_bars_mean_absolute_value
  Symptom:   Questions using |x| for absolute value were dropped as unsafe;
             the first fix turned ln|x| into the unknown name "lnabs".
  Cause:     "|" isn't on the whitelist, and replacing |x| with abs(x) glued it
             onto the function name in front of it.
  Fix:       Replace |...| with (abs(...)) before checking, so ln|x| becomes
             ln((abs(x))). An unmatched "|" is still refused.
  Files:     backend/mathcheck.py

[TEST-05] Checker thought |x| and x were the same
  Date:      Oct 25, 2026
  Found by:  probing the checker (now test_mathcheck.py::test_negative_values_are_checked)
  Symptom:   equivalent(|x|, x) and equivalent(sqrt(x^2), x) returned True.
             A "simplify sqrt(x^2)" question would have accepted x as correct.
  Cause:     The numeric spot checks only plugged in positive numbers
             (0.30 to 2.70), and these pairs agree for every positive x.
  Fix:       Test values now come from both [-2.7, -0.3] and [0.3, 2.7], with at
             least 3 usable points before trusting the result (otherwise fall
             back to sympy.simplify). log(x^2) vs 2*log(x) is also now
             correctly "different". Ordinary forms (sqrt(x), ln x, ln|x|, tan,
             e^x sin x) still check fine.
  Files:     backend/mathcheck.py

[TEST-04] Regenerating the art strips its content credentials
  Date:      Oct 24, 2026
  Found by:  byte-comparing SVGs before and after running generate.py
  Symptom:   Re-running generate.py changed every SVG even though the art was
             identical.
  Cause:     The committed SVGs carry an embedded C2PA "content credentials"
             manifest (provenance metadata marking them as AI-made). Freshly
             generated files don't have it.
  Fix:       Restored the original files. Lesson: after editing generate.py,
             only commit the SVGs whose art you actually changed, so the others
             keep their credentials.
  Files:     frontend/src/assets/mascot/

[TEST-03] generate.py crashed on Python 3.10
  Date:      Oct 24, 2026
  Found by:  running generate.py with Python 3.10
  Symptom:   SyntaxError: f-string expression part cannot include a backslash
  Cause:     An f-string had escaped quotes inside {...}, which only works on
             Python 3.12+.
  Fix:       Built that string with normal concatenation instead.
  Files:     frontend/src/assets/mascot/generate.py

[TEST-02] Limits were one-sided, so "no limit" questions got an answer
  Date:      Oct 25, 2026
  Found by:  test_mathcheck.py::test_bad_tasks_are_refused
  Symptom:   The checker said the limit of 1/x as x -> 0 is infinity. The real
             two-sided limit does not exist (left side is -infinity).
  Cause:     sympy.limit() computes the right-hand limit by default (dir="+").
  Fix:       Use dir="+-" for finite points, which raises an error when the left
             and right limits differ; those questions are now dropped.
  Files:     backend/mathcheck.py

[TEST-01] Quiz parser read "answer": "6" as option number 6
  Date:      Oct 24, 2026
  Found by:  writing test_api.py::test_parse_quiz_normalizes_and_shuffles
  Symptom:   A valid question whose correct option was the text "6" was thrown
             away.
  Cause:     The parser checked "is it a digit?" before "is it one of the
             options?", so "6" became index 6 (out of range).
  Fix:       Match the option text first, then letters (A-D), then digits.
  Files:     backend/app.py (parse_concept)

[MODEL-06] Tutor said "Not quite" to correct subtraction answers
  Date:      Oct 25, 2026
  Found by:  hand testing; then reading the 3 Subtraction sessions in clutch.db
  Symptom:   "7 - 2 = 5" got "Not quite."; "2-3=-1" (correct) was brushed off as
             "a statement"; "5-4" (a problem, no answer) got "Not quite."
  Cause:     The tutor judges answers with its own arithmetic ([OPEN-02]).
  Fix:       Before each tutor reply, mathcheck.find_claims looks at the
             student's message: full answers ("7 - 2 = 5", "3 + 4 is 7"), bare
             answers to the tutor's last question ("= 1", "5", "x = 5"), and
             problems with no answer ("5-4"). SymPy's verdict is added to the
             system prompt ("MATH ENGINE CHECK ... is CORRECT"). If the reply
             still has the wrong verdict ("Not quite." for a right answer, or
             "Yes" for a wrong one), it asks once more, then falls back to a
             short reply with the right verdict that doesn't reveal the answer.
             Applies to saved chats and /api/chat (so eval_tutor.py measures it).
  Not covered: calculus answers in chat ("Is it e^(x^2) + C?"), word problems.
  Files:     backend/mathcheck.py (find_claims, check_chat_answer),
             backend/app.py (tutor_reply, math_facts, verdict)

[MODEL-05] Wrong keys graded right answers as wrong (5 Addition quizzes regraded)
  Date:      Oct 25, 2026
  Found by:  hand checking quiz results; quizzes 4-5 were written at 1:03 am,
             a few minutes before SymPy was installed (1:07-1:09), so the
             checker was still off ([ENV-05])
  Symptom:   The student's answers were right, but bad keys scored the quizzes
             2-3/5, so no badge.
  Fix:       backend/regrade_quizzes.py re-checks saved quizzes, fixes keys,
             rescores from the answers actually given, and awards badges. Run on
             Oct 25: 13 keys fixed by the checker, 2 word problems fixed by hand
             (--set 3:3=C for 3 + 2 = 5, --set 4:5=C for 8 + 5 = 13), 1 word
             problem confirmed by hand (12 + 5 = 17). All 5 quizzes went to
             5/5 and the Addition badge was awarded, dated to quiz 1.
             Backup of the database from before: user_data/clutch-backup-20261025-011300.db
             Also: "Solve for x: 7 + x = 12" with options like "x = 5" is now
             checked.
  Usage:     cd backend; python regrade_quizzes.py           (preview)
                         python regrade_quizzes.py --apply   (backup + save)
                         python regrade_quizzes.py --set QUIZ:QUESTION=LETTER
             Submitted questions with no correct option are voided (everyone
             gets credit). Badges are never taken away.
  Files:     backend/regrade_quizzes.py, backend/mathcheck.py, backend/db.py,
             frontend/src/Quiz.jsx

[MODEL-04] Addition quizzes had wrong answer keys, even after the checker

[ENV-05] SymPy missing from the venv turns the checker off
  Date:      Oct 25, 2026
  Found by:  checking backend/.venv after bad Addition quizzes ([MODEL-04])
  Symptom:   Quizzes came back all unchecked; the only sign was a warning in
             the Flask terminal.

             Flask. The app now also says so: /api/health reports
             "math_checker": false, and the quiz page shows a red warning.
  Note:      An unsubmitted quiz is reused when a student comes back to it, so a

[ENV-04] After every pull: reinstall packages
  Python:    cd backend; pip install -r requirements.txt
             (sympy and mpmath were added for the quiz checker; without them the
             app starts but prints a warning and can't check math questions)
  Frontend:  cd frontend; npm install
             (react-markdown, remark-math, rehype-katex, katex were added)

[ENV-03] Keep package-lock.json in git
  Note:      It pins exact versions so both laptops run the same code, and it

 6. DESIGN DECISIONS
================================================================================

[DECISION-10] Offer textbook imports in the app
  Date:      Oct 25, 2026
  Why:       Students (and the demo) shouldn't need a terminal to get a course's book.
  How:       A course whose book isn't imported shows "Free textbook available" on
             the Progress page. "Import it" downloads in a background thread (real
             test: Psychology 2e in 3 s) while the page polls; failures (e.g. no
             internet) show a message and a Try again button. Only books listed in
             textbooks.BOOKS can be imported, and only when signed in.
             ALLOW_TEXTBOOK_IMPORT=0 turns it off.
  Files:     backend/app.py, backend/textbooks.py, frontend/src/Progress.jsx

[DECISION-09] OpenStax textbooks as a fourth way to check
  Date:      Oct 25, 2026
  Why:       Free, openly licensed books with official review questions and
             glossaries cover the courses our checkers can't (Biology, Economics,
             Psychology) and back up the ones they can.
  How:       import_openstax.py downloads the text only (~3% of the repo: Biology
             2e is 15 MB, parses in 0.5 s, 5.8 MB in the database) into its own
             textbooks.db. Quizzes use the book's questions first and skip the model
             when there are enough; chat gets 2-3 matching passages (at most 2500
             characters) instead of whole books, so prompts stay small for Gemma.
             Search is SQLite FTS5, a few ms. No new dependencies.
  License:   CC BY-NC-SA 4.0 (most) / CC BY 4.0 (Physics): read from each book's
             files and shown with the title and a link wherever the book is used.
             Book content stays out of git.
  Files:     backend/textbooks.py, backend/import_openstax.py, backend/app.py

[DECISION-08] Three ways to verify a course: calculate, look up, or quote the notes
  Date:      Oct 25, 2026
  1. Calculate: statistics/geometry (valuecheck.py), physics/chemistry
     (sciencecheck.py). Physics uses a fixed list of standard laws; the model never
     supplies a formula, since a wrong formula would make a wrong answer "verified".
     Units are converted and checked by a small built-in SI table (no new dependency).
  2. Look up: Spanish conjugations and English irregular forms (langcheck.py), and a
     social studies fact bank (factbank.py) whose questions are generated from facts.
     Words not in a table are never guessed.
  3. Quote: with notes in Materials, the model must quote the sentence behind each
     concept answer; groundcheck.py confirms the quote and that it supports the key.
     Weaker (word overlap), so it's labeled "checked against your notes".
  Verification levels: verified / partly verified / not verified, each listing what is
  and isn't checked. Everything runs offline.

[DECISION-07] Allow any course; verify only what we can check
  Date:      Oct 25, 2026
  Gemma isn't reliable for every subject (e.g. Spanish), but blocking courses would make
  the app less useful. So any course is allowed, and courses are matched to a catalog of
  standard courses (backend/courses.py). A catalog course is "Verified" only when the
  math engine checks its answer types and it's tested; each lists exactly what is
  checked, shown to the student. Suggestions combine Gemma (understands "times tables")
  with a keyword match (instant, works offline); exact name/topic keyword hits rank first.
  Typing a topic ("Addition") offers the course it belongs to, with that topic inside.
  Schema v4 adds subjects.catalog_id (the first ALTER TABLE migration).

[DECISION-06] Check math with SymPy and render from the checked expressions
  The model writes math quiz questions as SymPy tasks, and the question and
  options students see are generated from those same expressions, so what's
  shown always matches what was verified. Model output is untrusted: only
  whitelisted characters and function names are parsed, and each check runs in
  a worker process with a time limit (MATHCHECK_TIMEOUT, default 8 s).

[DECISION-05] Quiz rules
  Unlock at 80% topic mastery (same point the egg hatches), 5 questions (the
  model writes 7 so failed checks can be dropped), pass with 4/5 to earn the
  topic badge. Answers stay on the server until the quiz is submitted, and
  options are shuffled because small models tend to put the answer first.
  Settings: QUIZ_UNLOCK_MASTERY, QUIZ_PASS_FRACTION, QUIZ_QUESTIONS in .env.

[DECISION-04] How mastery is calculated
  Each ended session gets a score: 70% the model's read of the student's
  understanding, 30% the student's own 1-5 confidence rating. The first session
  sets mastery; later ones move it: mastery = 0.6 * old + 0.4 * new
  (MASTERY_WEIGHT in db.py). Egg stages: whole until studied, then cracks at
  0-30%, 30-55%, 55-80%, hatched from 80%.

[DECISION-03] Mother Hen art as code
  All mascot art is SVG generated by generate.py, so it stays sharp at any size
  and colors/poses can be changed by editing one file. Mascot.jsx gives
  <Hen pose="..."/>, <Egg mastery={...}/>, <Badge earned/>, <Logo/>.

[DECISION-02] Keep the stateless /api/chat endpoint
  Saved chats use /api/conversations/..., but /api/chat (nothing saved) stays so
  eval_tutor.py and chat_cli.py keep working unchanged.

[DECISION-01] SQLite for the database
  Built into Python, no server to run, one file (backend/user_data/clutch.db,
  git-ignored). Schema changes: edit schema.sql, bump SCHEMA_VERSION in db.py,
  add a migration only for changes schema.sql can't apply itself (e.g. new
  columns). Full details: docs/database.md.
